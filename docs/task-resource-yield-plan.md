# 任务资源收益统计规划

状态：R1 平台无关快照与差值契约已完成；R0 银币采集和 R2-R5 待实现（2026-08-03）

## 目标与口径

每个正式任务绑定一组执行前、执行后的角色资源快照，统计本次任务窗口内的经验、金币和银币净变化，并在运行历史与数据面板中展示。

- 展示名称统一为“净变化”，即 `after - before`，不把它误写成奖励总额。
- 自动恢复、系统赠送、离线奖励、活力自然恢复、人工操作或任务内消耗都可能影响净变化；存在这些干扰时降低归因可信度。
- 经验跨等级时不能直接用当前经验相减。只有等级变化和各级升级经验均可靠时才计算累计经验增量，否则保留前后值并标记“跨等级，增量待确认”。
- 金币、银币分别统计，不用总资产估值互相折算。

## 责任边界

资源采集不是每个任务内部重复实现的 Action，而是任务编排器统一调用的平台无关 `ResourceSnapshotWorkflow`：

```text
Task Orchestrator
  -> preflight
  -> ResourceSnapshotWorkflow(before)
  -> Task Workflow
  -> settle / restore gate
  -> ResourceSnapshotWorkflow(after)
  -> ResourceDeltaCalculator
  -> Run result + yield record
```

- Task Workflow 只返回任务状态、动作计数和业务结果，不知道背包、属性页或平台窗口 API。
- `ResourceSnapshotWorkflow` 负责打开只读页面、识别字段、关闭页面和恢复安全入口；macOS/Windows 仅提供平台适配器。
- 所有资源采集点击仍经过原子 Action、取消守卫、窗口标定、输入预算和结构化日志。
- Windows 后续直接复用快照与差值契约，只实现真实窗口、DPI、截图和输入适配，不复制收益逻辑。

## 执行时序与失败策略

### 执行前

1. 任务预检通过后，确认当前页面可以安全恢复。
2. 采集等级、当前经验、升级所需经验、金币和银币，并保存字段级 OCR/模板证据。
3. 恢复任务声明的起始页面并重新预检；恢复失败则不启动任务，避免产生无法归因的运行记录。
4. 任一核心字段缺失时默认阻止任务启动并提示重新采集。后续可增加显式“允许无收益统计运行”，但不能作为默认值。

### 执行后

1. 仅在任务实际执行并取得明确 `completed` 结果，且成功恢复到可采集页面后执行结束快照；固定次数耗尽但缺少完成证据时按安全停止处理，不采集或宣称任务收益。
2. 等待奖励动画和资源数字稳定；至少两次读取一致后才接受结束值，等待必须有时间上限。
3. 结束快照失败不篡改已经成立的任务结果；收益状态单独记为 `partial` 或 `unavailable`。
4. `cancelled`、未知页面安全停止、窗口失效或权限失败后不得为了采集继续导航。可以零输入读取当前可见字段，否则结束快照标记缺失。
5. 用户在任务期间产生输入、切换角色/窗口或运行其他采集时，将本次收益标记为“存在外部干扰”，不做强归因。

`already_completed` 表示本次没有执行任务，收益状态记为 `not_run`，不生成虚假的零收益，也不进入任务平均收益。

顺序任务中，如果前一任务的结束快照已经稳定、目标角色相同且中间没有输入或超时，可以把同一快照同时关联为下一任务的执行前快照，减少重复打开页面；数据库仍保存两个阶段关联。

## 数据模型

### 资源快照 `resource_snapshots`

- `id`、`target_id`、角色标识、采集时间、采集阶段 `before/after/standalone`。
- `level`、`experience`、`experience_required`、`gold`、`silver`。
- 每个字段的状态、原始 OCR、来源页面、识别框、截图/frame ID 和人工修正信息。
- 整体状态 `success/partial/failed`，以及恢复页面、失败阶段和错误原因。

### 任务收益 `task_resource_yields`

- `run_id`、`task_id`、`before_snapshot_id`、`after_snapshot_id`。
- `experience_delta`、`gold_delta`、`silver_delta`，允许为空。
- `attribution_status`：`reliable`、`interrupted`、`cross_level_unknown`、`partial`、`unavailable`、`not_run`。
- 任务开始/结束时间、耗时、任务结果、干扰原因和计算版本。

快照是原始事实，收益是可重新计算的派生记录。人工修正快照后重新计算差值并保留修正历史，不覆盖原始 OCR。

## 控制台展示

- 单次运行详情展示执行前、执行后和净变化：经验、金币、银币各自独立。
- 任务列表可展示最近一次可靠净收益；无完整快照时显示“未统计”，不显示 `0`。
- 数据面板按任务汇总总净变化、平均每次净变化、可靠样本数和单位时间净变化。
- 汇总默认只使用 `reliable` 样本；其他记录可查看但不进入平均值。
- CSV 导出同时包含原始前后值、差值、归因状态、任务结果和时间范围。

## 分阶段实施

### R0：银币采集前置

状态：待实机样本。当前仓库没有可核对的银币 OCR 框，禁止仅按背包 footer 顺序猜测。

- 在现有角色资源采集中加入银币识别、字段证据和失败口径。
- 在两种窗口尺寸下验证金币、银币、等级和经验读取及页面恢复。

### R1：平台无关快照契约

状态：已完成（2026-07-30）。

- 建立 `ResourceSnapshot`、字段证据、采集结果和差值计算器。
- 覆盖普通增减、负净变化、字段缺失、跨等级、人工修正和溢出值测试。

实现证据：`tools/resource_snapshots.py` 已提供 `ResourceValues`、字段证据、`ResourceSnapshot`、`ResourceYield` 和净变化计算器。16 项测试覆盖正负变化、单级/多级升级、缺失等级经验表、部分快照、角色或窗口变化、外部干预、时间顺序、`already_completed` 与不可用状态。

### R2：共享资源快照工作流

- 把现有金币/经验采集迁移为可复用 `ResourceSnapshotWorkflow`。
- 为打开背包、读取货币、打开属性、读取经验、关闭页面和恢复入口建立原子动作。

### R3：任务生命周期接入

- 由控制台编排器为每个正式 run 执行 before/task/after，不修改各任务业务循环。
- 第一批接入宝图、普通运镖和师门，再接签到、秘境、答题和捉鬼。
- 覆盖前置采集失败不启动、任务成功但后置采集失败、取消后零输入和顺序任务复用快照。

### R4：存储与界面

- 新增快照/收益关联、API、运行详情、按任务汇总和 CSV 导出。
- 历史任务没有收益记录时保持兼容，不补造零收益。

### R5：实机验收

- 每个白名单任务至少取得两组完整前后快照。
- 手工核对三项资源前值、后值和差值；验证一次升级场景、一次负金币/银币变化和一次主动取消。
- 确认结束采集不会领取奖励、消费资产或突破停止后零输入屏障。

## 完成标准

- 每个新任务 run 都有执行前快照；没有可靠前置快照时默认不启动。
- 正常完成的任务具有结束快照和可追踪的三项净变化，失败字段不会被当作 `0`。
- 跨等级、人工干预、取消和采集失败均有明确状态，不输出误导性收益。
- 收益统计不在 Task Workflow 中复制平台代码，macOS 和未来 Windows 共用同一数据及计算契约。
