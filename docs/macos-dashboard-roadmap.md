# macOS 控制台后续开发路线

本路线面向本机单用户、单游戏窗口场景。近期不扩展多账号、远程访问、任务队列和高风险资产操作，先把已开放的三界奇缘、科举乡试、捉鬼任务、福利签到、帮派签到以及金币/经验采集做成可重复、可停止、可诊断的闭环。

## 开发与提交原则

- 每个交付单元完成后运行对应测试、更新本路线和本地模块状态，并单独提交。
- 不把未经 macOS 实机验证的 `interface.json` 任务加入控制台白名单。
- 取消、识别失败、权限失败时优先停止点击并保留可恢复现场。
- 当前工作区已有的科举题库与识别改动先独立审查，不与控制台任务混合提交。

## 当前产品优先级

状态：已确认（2026-07-26）。

- 数据面板暂缓增加均值、成功率、区间高低等派生统计，优先接入游戏直接展示的原始数据。
- 第一批接入角色身份、金币/银币/仙玉/活力、等级/经验/评分，以及今日任务完成次数和可参与状态。
- 第二批接入装备、背包和宠物只读快照；市场行情继续保持只读，并排在角色与任务数据之后。
- 数据字段必须携带采集时间、来源页面和识别状态；低置信结果标记缺失，不猜测数值。
- 自动化任务按“现有五项实机收口 -> 日程中心只读识别 -> 师门/宝图/秘境 -> 日常副本 -> 周常/限时”推进。
- 每个功能完成对应测试后立即单独提交，不把多个未验收功能合并到同一提交。

## 里程碑 1：控制台运行闭环

目标：确认控制台不是只“能发起”，而是完整覆盖启动、恢复、并发拒绝、停止和结果记录。

### 1.1 状态恢复与接口回归

状态：已完成（2026-07-26）。

- 覆盖页面刷新后恢复当前任务、SSE 断线重连、重复启动返回 `409`。
- 覆盖后端重启后未完成运行的恢复策略，避免永久显示“运行中”。
- 为任务面板和数据面板补页面级测试，验证职责隔离和当天漏采提示。

验收：自动化测试可稳定复现上述场景；刷新页面不会丢失当前运行状态。

实现证据：后端启动时会将遗留运行标记为失败并记录耗时与恢复事件；SSE 支持 `Last-Event-ID` 续传和事件去重；前端连接恢复时重新获取系统状态；重复启动接口回归覆盖 `409`。

### 1.2 停止后零点击屏障

状态：实现与离线回归完成，待 macOS 实机验收（2026-07-26）。

- 在所有原生点击入口前统一检查取消令牌。
- `Tasker.post_stop()` 后等待适配器确认退出，并记录最后一次点击和停止完成时间。
- 对准备阶段、答题等待、战斗等待分别增加取消测试。

验收：停止接口返回后不再产生任何点击；任务最终状态为 `cancelled`，日志包含明确停止阶段。

实现证据：五个原生脚本共用信号取消守卫，停止时单次调用并等待 `Tasker.post_stop()`，所有点击、拖动和轮询等待均经过取消检查；控制台等待子进程退出及 `cancelled` 持久化后才响应，TERM 超时会升级 KILL；原生桥已移除窗口首次激活时的隐式第二次点击。假进程与输入屏障回归已通过，真实客户端仍需执行一次运行中停止观察。

### 1.3 启动前画面检测

状态：实现与自动化回归完成，待支持场景实机验收（2026-07-26）。

- 五个白名单任务均支持单帧、零输入的当前画面检测。
- 控制台展示当前页面、是否支持启动、建议下一步或阻塞原因；参数变化后旧结果立即失效。
- 检测与任务运行、启动游戏和指标采集互斥，15 秒超时后终止整个检测进程组。
- 检测只返回脱敏的识别计数与模板名，不创建运行记录、事件或成功率数据。

验收：在每项任务的支持页面和未知页面各检测一次；检测期间游戏不产生点击，运行记录及汇总保持不变。

实现证据：五个执行器统一输出唯一 `preflight_json=` 协议行；控制台严格校验协议结构，捉鬼嵌套证据与下一步动作已有回归覆盖；前端会丢弃参数变化后的迟到响应，并在请求真正结束前保持操作互斥。

### 1.4 五个白名单任务实机验收

- 三界奇缘：自动导航和手动入页各验证一次。
- 科举乡试：从正式答题页启动，验证本地题库命中和低置信停止。
- 捉鬼任务：验证一轮完成、指定轮数传入和主动停止。
- 福利签到：离线状态机与输入边界已完成，实机只读截图链路已验证；待游戏回到主界面后验证一次完整签到。
- 帮派签到：离线状态机与归一化位置边界已完成，活动列表场景实机预检能安全拒绝；待主界面或帮派页验证一次完整签到。

验收：每项任务至少一次从控制台启动并形成完整运行记录；错误提示能直接指导用户处理。

实现状态：控制台已为五项任务展示低/中/高风险标签；福利签到不领取累计 2/5/7 次奖励，帮派签到不领取分红，缺少明确画面证据时停止。

运行结果状态：五个白名单任务均已使用唯一 `result_json=` 最终协议，统一区分完成、今日已完成、达到本次上限、取消和安全停止；只有成功语义与退出码同时满足才计为成功，安全停止必须携带明确原因。结果会持久化到运行记录，并在最近运行中按任务展示答题数、点击数、捉鬼轮数、签到操作数或准确停止原因。旧数据库会自动增加可空结果列，历史记录保持兼容。

## 里程碑 2：指标采集可靠性

目标：让“立即自动采集”在常见窗口条件下无需人工干预，失败时能安全恢复。

### 2.1 多尺寸坐标与页面识别

- 建立支持窗口尺寸清单和统一坐标映射。
- 用页面特征确认主界面、背包和属性页，避免仅依赖固定延时。
- 在至少两种窗口尺寸下建立截图样本和离线识别测试。

验收：两种声明尺寸均可完成金币、等级、当前经验和升级所需经验采集。

### 2.2 采集事务与恢复

- 将采集拆成“识别起点 → 打开页面 → 读取 → 关闭 → 恢复主界面”阶段。
- 每阶段设置有限重试和取消检查；失败时尽最大可能关闭已打开页面。
- 记录原始 OCR、置信度、所用截图方式和失败阶段，供修正与诊断。

验收：任一阶段模拟失败均不会继续盲点；重复采集不会产生错误的趋势跳变。

### 2.3 数据质量与趋势规则

- 明确同等级经验变化、跨等级快照和人工修正的展示规则。
- 区分“采集失败”“字段缺失”“人工修正”和“任务未采集收益”。
- 验证本地时区下当天提醒、七天边界和多次快照聚合。

验收：跨等级时不伪造经验增量；修正记录可追踪；当天已有成功快照时不再提醒。

## 里程碑 4：角色与游戏数据接入

目标：把数据面板从金币/经验统计页调整为只读游戏数据中心。近期以接入更多游戏原始数据为主，不继续扩张派生统计，也不包含自动购买、出售或抢购。

状态：数据快照底座与首批资源视图已完成（2026-07-26），角色身份及其余资源字段待接入。

- 数据面板提供“角色概览”和“资源”视图，现有金币/经验数据迁入对应视图。

验收：支持字段可在声明窗口尺寸下重复采集；付费货币只读，不出现在任何自动消费流程中。

### 4.2 今日任务数据

状态：只读采集、存储接口与数据面板视图已完成（2026-07-26），待日程页实机验收和任务编排复用。

- 任务面板和数据面板复用同一份今日状态，已完成任务可在后续编排中自动跳过。

- 保存单件装备原始文本和结构化字段，低置信字段允许人工修正。
- 采集完成或中途失败时关闭详情页并恢复安全页面，不执行穿戴、分解、出售或打造。

验收：支持页面均能形成只读快照；识别不完整时标记缺失而非猜测；采集过程中不会触发任何资产变更。

### 4.4 市场价格关注清单（后置）

- 设置有限频率、最大翻页和最大搜索次数，避免无限浏览。

验收：同一物品可稳定定位并生成可追踪价格样本；样本不足或过期时不输出误导性估值；没有购买或出售入口。

### 4.5 资产估值、任务效率与提醒（后置）

- 基于有足够样本的市场数据估算背包材料和装备参考价值，明确区分账面数量与参考估值。
- 使用可靠的任务前后快照计算金币、经验和单位时间收益；无法建立因果关系时只展示快照变化。
- 支持价格突变、装备变化、物品临期和连续采集失败提醒。
- 所有估值显示数据时间、样本量和可信等级，不作为自动交易依据。

验收：缺少可靠价格时不计算总资产；跨等级经验不伪造增量；提醒可关闭且不会触发游戏操作。

## 里程碑 5：窗口标定与目标抽象

目标：在新机器首次运行、窗口尺寸或显示缩放发生变化时，先建立经过视觉证据验证的坐标映射；固定坐标不再直接依赖窗口外框和固定标题栏高度。

### 5.1 精确游戏窗口目标

- 增加 `targetId`，单窗口首版固定使用 `local-primary`，并记录进程 ID、窗口 ID、Bundle ID 和用户可见别名。
- 截图、点击和拖动始终绑定同一个精确窗口 ID，不在每次输入前按标题重新选择面积最大的窗口。
- 标定、任务方案、运行记录和游戏数据从首版开始携带 `targetId`，为后续多开保留稳定边界。

### 5.2 标定向导与标定配置

- 控制台首次运行时检查权限、目标窗口和已有标定，引导用户回到无遮挡主界面。
- 从单帧截图识别至少四个分布在不同边角的稳定锚点，计算游戏内容矩形、参考分辨率、统一缩放和偏移。
- 控制台展示带预测点击标记的截图供用户确认；自动锚点不足时允许用户在截图上指定锚点，不直接点击游戏。
- 保存窗口边界、内容边界、截图尺寸、显示缩放、截图方式、锚点误差、游戏版本和标定时间。

### 5.3 运行时标定门控

- 每次正式任务前重新读取窗口签名和关键锚点；尺寸、显示缩放、截图方式或锚点漂移超过阈值时阻止运行并要求重新标定。
- 旧固定坐标通过“参考坐标 -> 内容矩形”的缩放与偏移变换一次；OCR 和模板识别产生的实时框继续直接使用当前截图坐标，避免重复缩放。
- 只有内容宽高比和锚点误差均在支持范围内才允许等比例缩放；不对明显变形的窗口强行使用独立横纵拉伸。

验收：在新机器及至少两种窗口尺寸下完成标定，预测点落在声明控件内；移动窗口无需重标定，改变内容尺寸或显示缩放后会可靠失效；错误标定不会产生游戏输入。

## 里程碑 6：顺序任务编排

目标：用户可保存一组有顺序的自动化任务，控制台按顺序完成预检、执行、页面恢复和结果汇总，仍保持单窗口、单输入执行。

### 6.1 任务方案与步骤契约

- 增加任务方案和有序步骤模型，步骤保存任务 ID、参数、顺序、失败策略和启用状态。
- 每个任务声明支持的入口场景、成功结果、退出场景和是否要求恢复主界面。
- 支持添加、删除、启用、禁用和调整顺序；保存的方案在执行时生成不可变快照，编辑不会改变正在运行的批次。

### 6.2 编排执行与恢复

- 每一步开始前验证目标窗口、标定和当前画面，预检不通过时默认停止整个方案。
- `completed` 和 `already_completed` 进入下一步；`failed`、`safe_stopped` 默认终止，后续步骤标记为未执行。
- 在任务之间执行有界的安全页面恢复；无法确认主界面时停止，不连续尝试未知关闭按钮。
- 用户停止时终止当前子进程并取消剩余步骤；控制台重启后将未完成方案标记为暂停，不自动重放状态不确定的步骤。
- 后续接入今日任务快照，可靠显示已完成时可在执行前跳过对应步骤。

### 6.3 控制台编排界面

- 提供任务选择、参数编辑、上移/下移、方案保存和立即运行入口。
- 展示总进度、当前步骤、每一步状态、结构化结果和停止原因；单任务运行记录仍可独立查询。
- 首版不支持定时后台运行、无限循环、跨窗口并发和失败后自动重复点击。

验收：至少串联福利签到、帮派签到和一项答题任务；任一步失败或主动停止后不启动下一步；刷新和控制台重启后可恢复可解释的编排状态。

## 里程碑 7：诊断与产品化

- 将权限、窗口尺寸、连接失败转换为一步可执行的处理建议。
- 增加可导出的诊断包：任务摘要、阶段耗时、脱敏日志和必要截图。
- 落实实时日志保留 30 天的清理策略，任务记录和指标快照长期保留。
- 提供统一启动命令，自动检查 Python/前端构建、端口占用、游戏与系统权限。
- 在干净 macOS 环境完成安装、启动、采集和五任务验收。

验收：非开发者可按文档完成首次启动；常见故障无需查看源码即可定位。

## 里程碑 8：多开自动化（非常低优先级）

状态：仅保留架构兼容，不进入近期开发排期。必须在单窗口标定、顺序编排和五项任务实机稳定性全部验收后再启动。

- 每个游戏窗口拥有独立 `targetId`、精确窗口绑定、标定配置、任务方案、运行状态和数据快照。
- 调度器按目标管理资源锁；截图可独立进行，使用 macOS 全局输入的正式任务首版跨窗口串行，避免激活窗口时输入串线。
- 控制台按窗口展示任务、日志和数据，并明确当前正在接受输入的目标。
- 一个窗口失败或失去标定时只暂停对应目标，不影响其他窗口的数据和可恢复状态。
- 未证明精确窗口截图、激活和输入隔离前，不开放多窗口并行点击。

验收：两个同标题窗口可被稳定区分，所有截图和输入都能追踪到精确窗口 ID；串行切换运行不会点击错误窗口；单窗口行为和安全边界保持不变。
