# macOS 控制台后续开发路线

本路线面向本机单用户、单游戏窗口场景。近期不扩展多账号、远程访问和高风险资产操作，先把已开放任务、顺序编排以及金币/经验采集做成可重复、可停止、可诊断的玩家闭环。

## 开发与提交原则

- 每个交付单元完成后运行对应测试、更新本路线和本地模块状态，并单独提交。
- 不把未经 macOS 实机验证的 `interface.json` 任务加入控制台白名单。
- 取消、识别失败、权限失败时优先停止点击并保留可恢复现场。
- 当前工作区已有的科举题库与识别改动先独立审查，不与控制台任务混合提交。

## 当前产品优先级

状态：已调整（2026-07-30）。

- 暂停继续扩展新任务，先把共用输入流程重构为可复用、可审计的原子动作；窗口标定在统一 Action 入口上实现，避免每个任务分别接入坐标变换。
- 数据面板暂缓增加均值、成功率、区间高低等派生统计，优先接入游戏直接展示的原始数据。
- 第一批接入角色身份、金币/银币/仙玉/活力、等级/经验/评分，以及今日任务完成次数和可参与状态。
- 第二批接入装备、背包和宠物只读快照；市场行情继续保持只读，并排在角色与任务数据之后。
- 数据字段必须携带采集时间、来源页面和识别状态；低置信结果标记缺失，不猜测数值。
- 每个正式任务在执行前后采集经验、金币和银币快照，按净变化统计任务收益；详细时序、归因和失败口径见 [任务资源收益统计规划](task-resource-yield-plan.md)。
- 自动化任务按“现有五项实机收口 -> 日程中心只读识别 -> 师门/宝图/秘境 -> 日常副本 -> 周常/限时”推进。
- 每个功能完成对应测试后立即单独提交，不把多个未验收功能合并到同一提交。

## 玩家产品化实施顺序

状态：已纳入规划（2026-08-03）。来源见 [面向玩家的产品化改进建议](player-facing-product-suggestions.md)。

产品目标从“让玩家操作自动化工具”调整为“让工具替玩家完成当天计划”。建议归并为三条主线：

1. 降低理解成本：界面只使用玩家能直接理解的中文，不暴露状态码、IP、schema、快照等工程术语，也不把未接入字段展示成故障。
2. 建立安全感：默认展示当前任务、整体进度和可执行的处理建议；技术日志折叠但完整保留；停止入口显眼，停止结果只陈述已经验证的游戏状态。
3. 提供省事价值：以“一键完成今天的任务”为核心入口，后续支持任务选择、排序、记忆、预约和可靠的收益总结。

### P0-A：玩家化文案与信息收敛

实现状态（2026-08-02）：首轮前端展示优化已完成。任务中心、我的收益、权限状态和记录提示已改为玩家可理解的中文；今日进度成为首要信息，技术日志及收益统计默认折叠，未接入资源字段已隐藏。任务排序、一键全部和预约仍保留在后续 P0-C / P1 阶段，本轮未引入新的执行能力。

- 删除或改写界面中的英文 eyebrow、IP、内部状态码和技术统计名称，建立统一的玩家文案映射表。
- 将“采集/快照/指标/净变化”等词按场景改为“记录数据/金币/经验/本次变化”；开发诊断信息只出现在“查看详情”中。
- 未接入的银币、仙玉、活力和评分默认隐藏；只有已确定交付窗口时才显示“即将推出”，不显示“待接入”。
- 运行主视图只展示“正在做什么、进行到哪一步、是否需要玩家处理”；技术日志默认折叠，并继续支持刷新、重连和服务重启后的历史恢复。

验收：普通玩家首屏无需理解英文或工程术语；未实现能力不会被误认为故障；折叠日志后仍可查看完整脱敏记录。

### P0-B：权限、错误与停止体验

实现状态（2026-08-02，部分完成）：全局加载、连接、任务启动/检测、停止、数据更新和记录修正错误已统一为“发生了什么 + 怎么处理 + 重试入口”，原始异常默认折叠。停止状态已区分“停止请求中”“已停止输入”“现场待确认”，只有明确的主界面阶段证据才显示“已确认回到主界面”。首次运行向导已覆盖连接游戏、画面权限、操作权限、窗口检测和只读画面测试；权限步骤提供精确系统路径及受控的系统设置直达入口，测试复用零输入画面检查契约，完成状态保存在本机且可随时重新打开向导。真实系统设置截图因本轮 macOS 界面读取超时仍待补充。

- 首次运行向导覆盖连接游戏、屏幕录制、辅助功能、窗口检测和一次零风险测试，每一步提供系统设置路径和真实截图。
- 所有玩家可见错误采用“发生了什么 + 怎么处理 + 重新检测/重试入口”的结构；原始异常保留在详情中，不直接作为主提示。
- 运行中提供持续可见的停止按钮；停止后区分“已停止输入”“已确认回到主界面”和“现场状态待确认”，不得在没有画面证据时承诺游戏已经恢复。
- 安全说明明确自动化边界、资产操作限制和异常停止策略，不承诺不存在封号风险。

验收：新安装环境可仅按向导完成权限配置；常见窗口、权限和页面错误无需查看源码；停止确认后保持零输入，提示与实际恢复证据一致。

### P0-C：一键完成今天的任务

- 在里程碑 6 的顺序任务编排之上提供“一键开始”入口，默认方案只包含已通过实机稳定性矩阵的任务。
- 执行前读取可靠的今日任务状态，跳过已完成项；状态缺失或部分识别时不擅自跳过。
- 任一步失败、安全停止或用户停止时终止后续步骤，明确展示已完成、失败和未执行项。
- 第一版不包含定时启动、失败后自动重试、无限循环或高风险资产操作。

验收：至少串联福利签到、帮派签到和一项答题任务；一键运行与逐项运行使用相同的预检、停止屏障和结果契约；刷新或服务重启后可解释当前批次状态。

### P1：个性化计划、总进度与收益首屏

- 支持勾选任务、调整顺序并保存默认方案；编辑中的方案不改变正在运行的批次。
- 提供“今日完成 X/Y”、当前步骤和剩余步骤的大进度总览。预计剩余时间仅在同方案存在足够可靠历史样本时展示，否则只展示步骤进度。
- 支持显式预约每日运行，并提供执行前提醒和取消入口；预约复用已保存的顺序任务方案及其全部安全边界，不建立独立执行器。跑完后的“不处理/退出游戏/系统睡眠”等收尾选项后置，默认不执行关闭或睡眠。
- 数据首屏优先展示可靠前后快照计算出的“今天金币/经验变化”；独立快照、跨等级缺失或存在外部干预时降级为前后值，不宣称为任务收益。
- 均值、区间高低、采集成功率和 CSV 导出移入“详细数据”；趋势图增加简短文字结论，任务事件标记后置到 P2。
- 任务卡和游戏日程使用同一份今日状态来源；保留来源和更新时间，冲突时显示“待确认”，不在两个页面给出互相矛盾的完成结论。

验收：玩家可在一个首屏看清今天完成情况、当前动作和可靠收益；预约和收尾行为均可关闭、可追踪且不突破停止屏障；同一任务只有一套可解释的今日状态。

### P2：商业化与主动服务

- 增加账号、设备授权、激活码或订阅、到期提醒和离线宽限策略；授权失败不得影响用户停止正在运行的任务。
- 提供清晰的已支持任务、适用条件和开发中能力清单，未通过实机矩阵的任务不进入可运行列表。
- 增加连续采集失败、任务反复安全停止和资源异常变化提醒；提醒只提供诊断与处理入口，不自动执行资产操作。
- 趋势图支持任务事件标记，帮助玩家理解收益变化，但只有可靠快照允许建立任务关联。

验收：授权生命周期、断网、到期和设备变更有明确处理路径；异常提醒可关闭且不会触发游戏输入；功能清单与实际白名单一致。

实施顺序：先完成 P0-A 的前端文案与隐藏未完成功能，再完成 P0-B；P0-C 复用里程碑 6，不另建一套批处理执行器。任务收益按“里程碑 4.3 共享资源快照 -> 接入单任务生命周期 -> 供顺序编排复用边界快照”实施；预约按“统一返回主界面及 11 项实机矩阵 -> 任务前后资源快照接入 -> 里程碑 6 顺序编排 -> 里程碑 7 定时任务”的顺序实施。P2 在本地单用户闭环和发布安装流程稳定后启动。

## 里程碑 0：原子动作与任务工作流重构（当前）

目标：任务运行器只描述业务状态和动作组合；识别证据、点击/拖动、等待、取消、重复保护、输入预算和动作日志由平台无关 Action 层统一负责，macOS 和后续 Windows 通过适配器提供输入与截图能力。

- 建立平台无关的 `ActionScene`、`ActionInput`、`ActionWaiter`、`ActionContext`、`ActionResult`、`ActionMetrics`、共享输入预算和原子动作契约。
- Action 内核和日常领域动作不得导入 macOS/Windows 控制器；现有 `MacOSTaskRuntime` 只作为 `ActionInput` 适配器，Windows 后续实现同一协议。
- 第一批抽取打开活动、切换日常页签、点击活动卡片、双向滚动活动列表、继续右侧任务，以及证据点击动作。
- 宝图、普通运镖、师门、秘境降妖、福利签到、帮派签到、考古、三界奇缘、科举和捉鬼均已迁移；平台 runner 只负责识别源、适配器与协议装配。
- 三界奇缘和科举共用答案点击 Action，各自 Workflow 保留多选与同题等待规则；捉鬼的组队、目标调整、等级拖动、阵法、战斗等待和多轮状态由独立 Workflow 管理。
- 现阶段不逐项实机验收；已有功能全部适配后，再统一执行主界面入口、任务中间页、终态、异常页和停止屏障矩阵。
- 窗口尺寸变换、精确内容矩形和运行时标定只允许在共享运行时/Action 边界实现，任务不得自行维护另一套屏幕坐标换算。
- 跨平台依赖方向、Workflow 抽取门槛及暂缓实施的 Windows 分阶段计划见 [跨平台自动化架构与 Windows 后续规划](cross-platform-automation-plan.md)。

验收：同一原子动作只有一个实现和一组测试；迁移后的任务不直接调用底层点击/拖动；动作缺少新鲜画面证据、超过重复上限或共享预算时不产生额外输入；任务结果保持兼容。

实现证据：平台无关 Action 内核、通用几何层、日常领域动作及现有十项任务迁移已完成；福利刮卡使用有界多拖动 Action，帮派签到/分红使用独立一次性 Action，考古购买与挖掘使用独立预算，三界导航/多选、科举同题等待及捉鬼全状态循环均由平台无关 Workflow 管理。同一 Workflow 的双适配器契约覆盖无有效框、重复证据、共享预算、页签状态、滚动、单选、多选、等级拖动、精确轮次、只读预览和任务结果。按用户安排仅剩统一 macOS 实机回归，当前不实施 Windows。

## 里程碑 1：控制台运行闭环

目标：确认控制台不是只“能发起”，而是完整覆盖启动、恢复、并发拒绝、停止和结果记录。

### 1.1 状态恢复与接口回归

状态：已完成（2026-07-26）。

- 覆盖页面刷新后恢复当前任务、SSE 断线重连、重复启动返回 `409`。
- 覆盖后端重启后未完成运行的恢复策略，避免永久显示“运行中”。
- 为任务面板和数据面板补页面级测试，验证职责隔离和当天漏采提示。

验收：自动化测试可稳定复现上述场景；刷新页面不会丢失当前运行状态。

实现证据：后端启动时会将遗留运行标记为失败并记录耗时与恢复事件；SSE 支持 `Last-Event-ID` 续传和事件去重；前端连接恢复时重新获取系统状态；重复启动接口回归覆盖 `409`。

### 1.2 停止后零点击屏障

状态：实现与离线回归完成，待 macOS 实机验收（2026-07-26）。

- 在所有原生点击入口前统一检查取消令牌。
- `Tasker.post_stop()` 后等待适配器确认退出，并记录最后一次点击和停止完成时间。
- 对准备阶段、答题等待、战斗等待分别增加取消测试。

验收：停止接口返回后不再产生任何点击；任务最终状态为 `cancelled`，日志包含明确停止阶段。

实现证据：五个原生脚本共用信号取消守卫，停止时单次调用并等待 `Tasker.post_stop()`，所有点击、拖动和轮询等待均经过取消检查；控制台等待子进程退出及 `cancelled` 持久化后才响应，TERM 超时会升级 KILL；原生桥已移除窗口首次激活时的隐式第二次点击。假进程与输入屏障回归已通过，真实客户端仍需执行一次运行中停止观察。

### 1.3 启动前画面检测

状态：实现与自动化回归完成，待支持场景实机验收（2026-07-26）。

- 五个白名单任务均支持单帧、零输入的当前画面检测。
- 控制台展示当前页面、是否支持启动、建议下一步或阻塞原因；参数变化后旧结果立即失效。
- 检测与任务运行、启动游戏和指标采集互斥，15 秒超时后终止整个检测进程组。
- 检测只返回脱敏的识别计数与模板名，不创建运行记录、事件或成功率数据。

验收：在每项任务的支持页面和未知页面各检测一次；检测期间游戏不产生点击，运行记录及汇总保持不变。

实现证据：五个执行器统一输出唯一 `preflight_json=` 协议行；控制台严格校验协议结构，捉鬼嵌套证据与下一步动作已有回归覆盖；前端会丢弃参数变化后的迟到响应，并在请求真正结束前保持操作互斥。

状态：截图签名变化、旧帧、PID/尺寸变化门控与输入前实时窗口复核已完成（2026-07-30）；四锚点和双尺寸实机验收待完成。

- 每次正式任务前重新读取窗口签名和关键锚点；尺寸、显示缩放、截图方式或锚点漂移超过阈值时阻止运行并要求重新标定。
- 旧固定坐标通过“参考坐标 -> 内容矩形”的缩放与偏移变换一次；OCR 和模板识别产生的实时框继续直接使用当前截图坐标，避免重复缩放。
- 只有内容宽高比和锚点误差均在支持范围内才允许等比例缩放；不对明显变形的窗口强行使用独立横纵拉伸。

实现证据：截图层为 Maa 和系统 fallback 生成统一 `CaptureSignature`。系统 fallback 保留缩放前的窗口截图尺寸、内容裁剪区和像素倍率，因此固定输出为 `1020×718` 时仍能发现窗口或显示缩放变化；PNG 优先使用 alpha 通道确定窗口轮廓，避免黑色游戏画面污染边界。`MacOSTaskRuntime` 首帧锁定签名，Scene 携带同一原始帧；统一 backend 在输入或预测前复核 PID、尺寸和 frame ID，并使用 `content_rect_points` 映射，不再猜测 28 点标题栏。预检会输出窗口边界、内容矩形、缩放和 frame ID，有识别框时输出中心像素与预测屏幕点；预览不调用输入，四锚点完成前标记 `anchorValidation: pending`。2026-07-30 只读实机探测绑定窗口 `6637`，取得 Maa `923×720` 帧及 `0.8782112274` 缩放，全程没有点击或拖动。

验收：在新机器及至少两种窗口尺寸下完成标定，预测点落在声明控件内；移动窗口无需重标定，改变内容尺寸或显示缩放后会可靠失效；错误标定不会产生游戏输入。

## 里程碑 6：顺序任务编排

目标：用户可保存一组有顺序的自动化任务，控制台按顺序完成预检、执行、页面恢复和结果汇总，仍保持单窗口、单输入执行。

### 6.1 任务方案与步骤契约

- 增加任务方案和有序步骤模型，步骤保存任务 ID、参数、顺序、失败策略和启用状态。
- 每个任务声明支持的入口场景、成功结果、退出场景和是否要求恢复主界面。
- 每个步骤关联执行前/后资源快照和收益状态；相邻步骤只有在目标相同、快照稳定且中间零输入时才能复用同一边界快照。
- 支持添加、删除、启用、禁用和调整顺序；保存的方案在执行时生成不可变快照，编辑不会改变正在运行的批次。

### 6.2 编排执行与恢复

- 每一步开始前验证目标窗口、标定和当前画面，预检不通过时默认停止整个方案。
- `completed` 和 `already_completed` 进入下一步；`failed`、`safe_stopped` 默认终止，后续步骤标记为未执行。
- 在任务之间执行有界的安全页面恢复；无法确认主界面时停止，不连续尝试未知关闭按钮。
- 用户停止时终止当前子进程并取消剩余步骤；控制台重启后将未完成方案标记为暂停，不自动重放状态不确定的步骤。
- 后续接入今日任务快照，可靠显示已完成时可在执行前跳过对应步骤。

### 6.3 控制台编排界面

- 提供任务选择、参数编辑、上移/下移、方案保存和立即运行入口。
- 展示总进度、当前步骤、每一步状态、结构化结果和停止原因；单任务运行记录仍可独立查询。
- 首版不支持定时后台运行、无限循环、跨窗口并发和失败后自动重复点击。

验收：至少串联福利签到、帮派签到和一项答题任务；任一步失败或主动停止后不启动下一步；刷新和控制台重启后可恢复可解释的编排状态。

## 里程碑 7：定时任务与预约（后置）

状态：已规划，暂不实施（2026-08-03）。必须在统一返回主界面的 11 项 macOS 实机矩阵通过、里程碑 6 顺序编排稳定后启动。

目标：用户可以为已保存的任务方案设置每日预约；定时器只负责触发同一套编排入口，不绕过预检、任务完成证据、返回主界面、停止屏障或运行互斥。

### 7.1 预约模型与持久化

- 预约关联 `targetId` 和不可歧义的已保存方案，保存启用状态、本地时区、执行时间、适用星期、下次触发时间、上次触发时间和结果。
- 首版只支持每天或指定星期的单次时间点，不开放任意 cron、循环间隔、并发计划或远程触发。
- 修改方案或预约时生成新的版本；已经触发的批次使用不可变方案快照，避免运行途中被编辑改变。
- 服务重启后根据持久化状态重新计算下一次触发，但不重放状态不确定的历史触发。

### 7.2 触发、冲突与错过策略

- 到点后先确认控制台服务、游戏进程、目标窗口、权限、标定和无遮挡起始页面，再调用里程碑 6 的编排入口；任一预检失败均零输入并记录可处理原因。
- 已有任务、资源记录、只读检测或其他预约正在占用目标时，首版将本次触发标记为“因冲突跳过”，不排队，也不在占用结束后突然补跑。
- 控制台未运行、电脑睡眠或游戏未启动造成的错过，首版默认跳过并提示用户，不自动追赶；补跑策略待真实使用数据证明有需要后再单独设计。
- 当天方案内已明确完成的任务继续由编排器跳过；今日状态缺失、冲突或不可靠时，不把任务猜测为完成。
- 时区、夏令时和系统时间变化后重新计算未来触发；同一个计划在同一游戏日最多自动触发一次。

### 7.3 提醒、控制与安全边界

- 前端展示下一次预约时间、启用状态和上次结果；触发前提供醒目提醒及取消入口，运行后复用全局“请勿操作游戏窗口”提示和停止按钮。
- 用户可随时禁用未来预约；停止已经触发的批次时复用当前停止契约，并取消该批次剩余步骤，但不擅自修改用户的长期预约开关。
- 首版不自动启动或登录游戏、不唤醒电脑、不自动重试失败任务、不执行无限循环，也不在结束后退出游戏或让系统睡眠。
- 恢复主界面失败、任务安全停止、用户停止或服务中断后，本次预约终止，不自动再次点击或启动补偿批次。

### 7.4 验证与验收

- 使用可控时钟覆盖准时触发、跨午夜、星期切换、时区变化、服务重启和同一游戏日去重。
- 覆盖游戏未启动、窗口丢失、权限缺失、标定失效、已有运行、用户临时取消和触发后停止，确认所有阻塞路径均为零输入。
- 验证预约批次与手动批次使用相同的方案快照、任务结果、返回主界面和今日完成口径；不得出现第二套任务执行状态机。

验收：连续七天测试中每个有效预约最多触发一次；冲突和错过不会迟到补跑；任一步失败或用户停止后不启动后续步骤；刷新和服务重启后可解释下一次执行时间与上次结果。

### 7.5 周常任务提前提醒（后置）

- 根据任务注册表中的开放星期和时段计算下一次周常任务，不为每项任务另外硬编码日期判断。
- 默认在开放前一天于控制台内提醒，后续允许用户选择提前天数或关闭提醒；需要系统通知时必须单独取得 macOS 通知权限。
- 提醒包含任务名称、开放时间和进入周常任务标签页的入口，但不自动启动游戏、任务或预约方案。
- 同一任务的同一开放周期只提醒一次；用户关闭后持久化到该周期结束，刷新和服务重启不重复打扰。
- 已完成、已过开放期、任务配置失效或日程证据不可靠时不发送误导性提醒；提醒状态不得改变今日完成状态。

验收：覆盖开放前、开放当天、跨周、时区变化、刷新重连、关闭提醒和任务已完成；每个开放周期最多提醒一次，任何提醒路径均不产生游戏输入。
